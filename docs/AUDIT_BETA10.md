# Beta 10 Spotify bulk selection audit

The Ctrl+A stall combined repeated full native-list renders on each fetched page with a vector membership check for each mark. Selection now records the whole source without eager page requests, tracks excluded URIs, and uses an indexed ordered set for materialized selections. Only a bulk action asks the Spotify worker to enumerate URI pages; it releases each page and retains distinct playable URIs. This avoids row hydration, per-page saved-state lookups, and native list growth. Worker progress is reported every 500 songs without moving focus. A captured selection snapshot preserves exclusions if marking changes during the read; leaving the list drops unresolved work from the UI.

The source and target playlist URI reads run off the UI thread. Writes use batches of 100, preserving order. Failures keep the marked selection for retry rather than reporting false completion. Saved states are checked in bounded batches and must be complete; writes are read back and must match the requested state. Mixed liked selections can save only new songs or all songs. Bulk unlike asks for confirmation; unknown saved states offer Save. Liked Songs itself is known fully saved even when only its first page is displayed.

Regression coverage: ordered deduplication of 13,500 URIs; 13,501-item whole-source selection with one exclusion; partial-page Ctrl+A keeps visible rows and performs no service request; mixed, all-liked and unliked selection menu labels; existing mark/toggle/focus tests. Cross-target Windows type checking and Clippy supplement native Mac tests. Live account-scale mutations and complete NVDA/VoiceOver speech remain unverified. No user installation, profile, or account data was modified during tests.
