# What's new in version 2.0.0-beta.8

## Playback

- Switching from Spotify to YouTube starts playback on the first attempt, even after returning with Escape. The new media no longer inherits mpv's old PCM pause state.
- A Spotify disconnection no longer leaves stale PCM mode that incorrectly fails the next ordinary media item.
- Closing the Spotify player also stops its decoder and Connect transport instead of leaving an unconsumed audio stream behind.
- Shuffle keeps your On or Off choice while the player area remains open, including opening another track or returning with Escape. Close resets the session. Spotify loads use the same retained mode and preserve repeat during an open playback session.
- macOS background playback keeps accessible player controls beside the previous screen. The configured background play/pause shortcut is registered globally.
- macOS uses Command+Shift+Space consistently for background play/pause. The old default migrates from beta 6/7; other custom and disabled bindings remain intact. Character bindings follow the active keyboard layout.
- When focus is in the player controls, shortcuts and Shift+F10 target the playing item. With focus in a list, they retain selected-row behavior. This includes Spotify Like/Unlike, radio and supported Hide operations.

## macOS parity

- Spotify lyrics and episode transcripts use Spotify's own route before the generic fallback.
- Resume last session, Copy link, Copy diagnostic report and result-column navigation now have working handlers.
- YouTube results receive missing metadata, prioritizing the selected row without disturbing focus. Next-stream prefetch now follows the existing settings and cache policy.
- Spotify search fields retain native typing, deletion and Return submission.
- Windows-data import validates collection structure, stages every file, restores originals on failure and prevents old controllers from overwriting imported data during shutdown.

## Updates and diagnostics

- A macOS yt-dlp update must report its version successfully before replacing the working component.
- The macOS application updater keeps its backup until the new bundle passes its startup check and restores the old bundle if it fails.
- Component checks cannot overlap. Diagnostic reports redact macOS home and temporary folders.
- Disabled keyboard shortcuts stay disabled after restarting on both platforms.
- LibreSpot is compiled into ApricotPlayer, including local Connect fixes. It updates with ApricotPlayer; an independent yt-dlp-style update button would not update this engine. The current pinned version matches the official latest release, 0.8.0.

## Packages

The release includes the Windows installer and portable ZIP, the Apple silicon macOS DMG, and the macOS ZIP required by the existing application updater.

The macOS application is ad-hoc signed and not notarized. After copying it to Applications, macOS may require a one-time Open Anyway approval in System Settings, Privacy & Security. Use only the official release asset.

## Verification limits

The detailed review is in `docs/AUDIT_BETA8.md`. Regression tests reproduce failures before fixes; automated tests and native accessibility checks do not certify every NVDA/VoiceOver speech or real-account scenario.

The macOS global hotkey handler passed native Carbon dispatch and pause checks. Application-targeted key injection could not validate a physical global keypress from another foreground application; that runtime check remains outstanding.

The beta 7 account-dependent Liked Songs reopening issue did not reproduce in the actual offline LibreSpot task and is not claimed fixed. Spotify Smart Shuffle is not claimed verified by ordinary shuffle tests.
