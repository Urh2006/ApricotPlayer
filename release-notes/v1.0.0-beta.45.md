# ApricotPlayer 1.0.0 Beta 45

This beta is a security and reliability release. It does not change the player's sound, EQ tuning, seek behavior, or normal fast playback path.

## Security
- App and yt-dlp updates now require published SHA-256 digests and remain on trusted HTTPS hosts.
- Update downloads and metadata have strict size limits. ZIP packages are checked for traversal, unsafe Windows paths, links, duplicate entries, oversized files, and compression bombs.
- Portable updates now replace `ApricotPlayer.exe` and the complete `_internal` folder together. If copying fails, both old components are restored.
- RSS, OPML, podcast chapters, transcripts, lyrics, YouTube API data, and browser DevTools responses are parsed with safer XML handling, bounded reads, and redirect checks.
- Browser-cookie export keeps only YouTube/Google-related cookies. Diagnostic reports now redact credentials, signed URL parameters, proxy login data, cookie signatures, and user-profile paths.
- Build dependencies and bundled runtimes are version-locked and verified. A scheduled GitHub security workflow now audits dependencies and runs the regression suite.

## Reliability
- App state files now use atomic writes so a crash or overlapping background save cannot leave half-written JSON.
- Older background history, session, and stream-cache saves can no longer overwrite newer state.
- mpv IPC requests now honor their timeout without a blocking pipe read.
- Cache cleanup is restricted to ApricotPlayer-owned files and avoids links or reparse points.
- Download templates and generated Windows paths reject traversal, device names, unsafe extensions, and other invalid layouts.

- Dependency audit reports no known vulnerabilities in the locked build set.
- Source GUI startup, real mpv IPC, EQ with clipping limiter, Rubberband speed/pitch, FFmpeg, yt-dlp, portable installation, and forced updater rollback were tested successfully.
